# פעולות · ספריית השראה למדריכים בבני עקיבא

אתר סטטי בעברית שנועד לתת למדריכים בני 16 רעיון טוב לפעולה תוך כמה שניות.
המאגר כולל משחקים, פעולות לדוגמה, תוכנית שנתית לפי הלוח העברי, ותוכן לחגים.

**באתר אין AI, אין שרת, אין מסד נתונים ואין הרשמה.** כל התוכן נוצר מראש ונשמר כקבצי JSON.
ה-AI שימש רק בשלב הפיתוח כדי לבנות את המאגר.

---

## הפעלה מהירה

```bash
npm run serve
```

ואז לפתוח את http://localhost:8080

> חשוב: אי אפשר לפתוח את `docs/index.html` בלחיצה כפולה. הדפדפן חוסם טעינת קבצי נתונים מהדיסק.
> צריך שרת - או `npm run serve` מקומית, או אחסון סטטי אמיתי.

## מבנה הפרויקט

```
content/          ← כל התוכן. כאן עורכים.
  games/          ← מאגר המשחקים, מחולק לקבצים לפי סוג
  activities/     ← פעולות מלאות (3 משחקים + מסר)
  holidays/       ← תוכן לחגים ומועדים
  calendar/       ← לוח השנה העברי והתוכנית השנתית
    year-5787.json      ← נוצר מ-Hebcal, לא לערוך ידנית
    holidays-5787.json  ← נוצר מ-Hebcal, לא לערוך ידנית
    plan-5787.json      ← התוכנית השנתית: נושא לכל שבוע
  rules/          ← כללי שבת מפורשים
  taxonomy.json   ← אוצר המילים המבוקר (קטגוריות, נושאים, משפחות משחקים)

schema/           ← תדריכי כתיבה: מה מותר ומה חובה בכל רשומה
scripts/          ← בנייה ובדיקות
docs/             ← האתר עצמו. זו התיקייה שמעלים לאוויר (השם docs/ נדרש ע"י GitHub Pages).
  data/           ← נוצר אוטומטית ע"י npm run build. לא לערוך.
```

**הפרדה בין תוכן לקוד:** אין אף משפט של תוכן בתוך הקוד. אפשר להחליף את כל המאגר בלי לגעת באתר.

## איך מעדכנים תוכן

### להוסיף משחק

1. פותחים את הקובץ המתאים ב-`content/games/` (או יוצרים קובץ חדש - כל קובץ JSON בתיקייה נטען אוטומטית).
2. מוסיפים רשומה לפי `schema/BRIEF-games.md`. **חובה לקרוא אותו** - הוא מסביר את כל השדות ואת כללי האיכות.
3. מזהה חדש: `g-<קידומת הקובץ>-<מספר>`, למשל `g-mov-26`.
4. מריצים:

```bash
npm run check
```

### להוסיף פעולה

1. מוסיפים רשומה ב-`content/activities/` לפי `schema/BRIEF-activities.md`.
2. שדה `games` מכיל בדיוק 3 מזהי משחקים **שקיימים במאגר**.
3. בפעולת שבת - כל שלושת המשחקים חייבים להיות מסומנים `shabbat: true`.
4. `week_index` קובע לאיזה שבוע בתוכנית השנתית הפעולה משובצת.

### לשנות את התוכנית השנתית

עורכים את `content/calendar/plan-5787.json` (נושא, רעיון, theme לכל שבוע).
התאריכים חייבים להישאר זהים ל-`year-5787.json` - הבדיקה תתריע אם לא.

### לבנות שנה חדשה

```bash
npm run build-calendar
```

הסקריפט שולף מ-Hebcal (לוח ישראל, עברית) את החגים, הפרשות והתאריכים העבריים, ושומר אותם בקבצים.
לפני כן משנים ב-`scripts/build-calendar.mjs` את `HEBREW_YEAR`, `YEAR_LABEL`, `START` ו-`END`,
ומוחקים את `content/calendar/_raw/` כדי לשלוף מחדש.
**התוצאה נשמרת בקבצים - האתר לעולם לא פונה לרשת.**

## הפקודות

| פקודה | מה היא עושה |
|---|---|
| `npm run serve` | שרת מקומי לתצוגה |
| `npm run validate` | כל בדיקות ה-QA על התוכן. נכשלת עם קוד שגיאה אם יש בעיה |
| `npm run check-duplicates` | מאתרת משחקים כפולים או דומים מדי |
| `npm run check` | שתי הבדיקות יחד |
| `npm run link-plan` | משבצת את הפעולות שנכתבו לתוך התוכנית השנתית |
| `npm run build` | מאחדת את `content/` לקבצי הנתונים של האתר ב-`docs/data/` |
| `npm run release` | שרשרת מלאה: שיבוץ, בדיקות ובנייה |
| `npm run build-calendar` | בונה מחדש את לוח השנה העברי מ-Hebcal |
| `npm run make-pools` | כלי פיתוח: מחלק את המשחקים למאגרים לכתיבת פעולות |
| `node scripts/init-plan.mjs` | יוצר שלד תוכנית שנתית ריק מתוך לוח השנה (תאריכים נעולים) |
| `node scripts/pick-activity-slots.mjs` | בוחר לאילו מועדים תיכתב פעולה מלאה, לפי מכסה ועדיפות לחגים |

### למה יש מאגרי משחקים נפרדים (`make-pools`)

כל פעולה צורכת 3 משחקים, והכלל הוא שאותו משחק לא חוזר בתוך 26 שבועות.
לכן מספר הפעולות שאפשר לכתוב בכל רבע שנה מוגבל בגודל מאגר המשחקים.
`make-pools` מחלק את המשחקים לשלושה מאגרים זרים ומצמיד כל רבע שנה למאגר,
כך שרבעים שקרובים זה לזה לעולם לא יכולים לבחור את אותו משחק. רבעים שרחוקים
יותר מ-26 שבועות חולקים מאגר, כי שם החזרה מותרת ממילא.

### מה `npm run validate` בודק

* לכל משחק יש מזהה, ואין מזהים או שמות כפולים
* כל שדות החובה קיימים ובטיפוס הנכון
* טווחי הגילאים מכילים את גיל 12, וטווחי המשתתפים מכילים 40 חניכים
* כל הערכים המסווגים קיימים ב-`taxonomy.json`
* **משחק שמסומן `shabbat: true` אינו מכיל אף מילה או ציוד מרשימת האיסורים**
* משחק שאינו לשבת מסביר למה (`shabbat_reason`)
* כל פעולה מפנה למשחקים קיימים, ובדיוק שלושה
* **פעולת שבת מכילה רק משחקים שמותרים בשבת**
* כל התאריכים תקינים, ימי שלישי הם באמת שלישי ושבתות הן באמת שבת
* **אותו משחק אינו חוזר בתוכנית בתוך פחות מ-26 שבועות**
* אותה משפחת משחקים אינה חוזרת בפער קטן מדי

## כללי השבת

הקובץ `content/rules/shabbat-rules.json` הוא המקור היחיד לאמת בנושא.
המערכת **אינה פוסקת הלכה** - היא עובדת לפי רשימה סגורה של פעולות וציוד שאסורים בפעולת שבת
(כתיבה, ציור, גזירה והדבקה, טכנולוגיה, אש וחשמל, כסף, זריעה, בלונים, קריעה, מיון חפצים).

עקרון העל: **בכל ספק - המשחק לא מסומן כמתאים לשבת.**

הבדיקה האוטומטית סורקת את הטקסט המלא של כל משחק שבת ופוסלת אותו אם מופיעה בו מילה אסורה,
גם בשלילה. לכן במשחק שבת כותבים "בעל פה" ולא "בלי לכתוב".

לשינוי המדיניות עורכים רק את קובץ הכללים ומריצים `npm run validate`.

## פריסה לאוויר

התיקייה `docs/` היא אתר סטטי שלם. אין תהליך build של קוד.

### GitHub Pages

```bash
npm run release
git add -A && git commit -m "עדכון תוכן"
git push
```

ובהגדרות המאגר: Settings → Pages → Source: Deploy from a branch → הענף שלכם → תיקייה `/docs`.
(GitHub Pages תומך רק ב-`/` או ב-`/docs` בלי GitHub Actions - לכן שם התיקייה קבוע.)

### Cloudflare Pages

חיבור המאגר, Build command: `npm run release`, Output directory: `docs`.

> אחרי כל שינוי תוכן חובה להריץ `npm run build` - האתר קורא רק מ-`docs/data/`.

## עקרונות שלא כדאי לשבור

1. **אין AI בזמן ריצה.** לא OpenAI, לא Anthropic, לא שום API. המדריך לא מדבר עם בוט.
2. **אין backend, אין משתמשים, אין הרשמה.** נכנסים ומוצאים רעיון.
3. **התוכן לא נמצא בקוד.** הקוד קורא JSON, זה הכול.
4. **בספק לגבי שבת - לא מסמנים כשבת.**
5. **לא ממציאים מקורות יהודיים.** מוטב בלי מקור מאשר מקור שלא בטוח בו.
6. **איכות לפני כמות.** 150 משחקים מעולים עדיפים על 300 בינוניים.
