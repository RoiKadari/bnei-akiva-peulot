# תדריך כתיבת משחקים למאגר

הקובץ הזה הוא המקור היחיד לאמת עבור כל מי שכותב משחקים למאגר (בין אם אדם ובין אם סוכן AI).
מי שכותב batch של משחקים חייב לקרוא אותו במלואו, וגם את `content/taxonomy.json` ו-`content/rules/shabbat-rules.json`.

---

## 1. למי זה מיועד

* **החניכים:** בני 12, בנים ובנות, **כ-40 חניכים בפעולה**.
* **המדריכים:** 4 מדריכים בני 16, לא אנשי חינוך. הם קוראים את המשחק בטלפון דקה לפני הפעולה וצריכים להבין אותו מיד.
* **המקום:** סניף בני עקיבא - חדר גדול או חצר.

## 2. שלושת מבחני הסף

משחק שלא עובר את שלושתם - לא נכנס למאגר:

1. **מבחן ה-40:** האם 40 חניכים באמת משתתפים בו-זמנית? משחק שבו 38 ילדים עומדים ומסתכלים על 2 - נפסל, אלא אם כתוב במפורש איך מריצים אותו במקביל בכמה קבוצות.
2. **מבחן המדריך בן ה-16:** האם אפשר להסביר אותו ב-60 שניות, בלי הכנה של שעה ובלי ציוד מסובך?
3. **מבחן הערך:** האם קורה פה משהו חברתי אמיתי - שיתוף פעולה, הקשבה, אתגר, צחוק משותף - או שזה סתם מילוי זמן?

## 3. כללי שבת

* `shabbat: true` רק אם המשחק עובר את הכללים ב-`content/rules/shabbat-rules.json`.
* **בכל ספק - `false`.**
* כשמסמנים `false`, חובה להוסיף `shabbat_reason` במשפט קצר ("דורש כתיבה על דפים").
* **חשוב:** במשחק שמסומן `shabbat: true` אסור שיופיעו מילים אסורות בטקסט - **גם לא בשלילה**. לא לכתוב "בלי לכתוב" אלא "בעל פה". הבדיקה האוטומטית פוסלת את המילה עצמה.
* ציוד מותר בשבת: ראו `allowed_equipment`. כרטיסיות שהוכנו לפני שבת - מותרות ומועילות מאוד.

### כללי שדות

| שדה | כלל |
|---|---|
| `id` | לפי ה-prefix שהוקצה ל-batch שלכם, דו-ספרתי: `g-mov-01`. אין לחרוג מה-prefix. |
| `name` | 1-4 מילים. שם שאפשר לצעוק בסניף. לא "משחק שיתוף פעולה מספר 3". |
| `description` | 1-2 משפטים, עד ~25 מילים. מה החניך עושה בפועל. |
| `instructions` | מערך של 3-6 שלבים. כל שלב משפט אחד עד שניים. **חייב לכלול איך מחלקים 40 חניכים ואיך המשחק נגמר.** |
| `duration_minutes` | 5-25. ריאלי, כולל הסבר. |
| `min_participants` / `max_participants` | חייב להכיל את 40. בדרך כלל 15-20 עד 50-60. |
| `age_min` / `age_max` | חייב להכיל את 12. בדרך כלל 10-15. |
| `equipment` | מערך. אם אין - `["ללא ציוד"]`. ציוד שקיים בכל סניף בלבד. |
| `preparation` | מה להכין לפני. אם אין - "אין צורך בהכנה". |
| `energy_level`, `group_structure`, `location`, `categories`, `topics`, `game_family` | **רק ערכים מתוך `content/taxonomy.json`.** |
| `categories` | 1-3 ערכים. |
| `topics` | 0-3 ערכים. באיזה נושא חינוכי המשחק יכול לשמש כקרש קפיצה. |
| `educational_goals` | 1-2 משפטים קצרים - מה החניך מרגיש/מבין דרך המשחק. לא סיסמאות. |
| `game_family` | ערך אחד. זה השדה שמונע חזרתיות - ראו סעיף 5. |
| `notes` | הטיפ שמציל את המדריך: מה משתבש, איך מקצרים, מה עושים עם מי שנפסל. |
| `variations` | 0-2 ווריאציות בשורה אחת. ווריאציה שמאפשרת גרסת שבת - זהב. |

## 5. משפחות משחקים (`game_family`)

זה השדה הכי חשוב למניעת חזרתיות. "העברת כדור", "העברת בלון" ו"העברת טבעת" הם **אותו משחק** מבחינת החניך - כולם `pass_object`.
בחרו את המשפחה לפי **מה החניך עושה בפועל**, לא לפי הנושא. אם משחק לא מתאים לאף משפחה - בחרו את הקרובה ביותר וציינו זאת ב-`notes`; אין להמציא ערכים חדשים.

## 6. סגנון כתיבה

* עברית פשוטה, גוף שני או סתמי ("מחלקים", "כל קבוצה בוחרת"). לא לשון גבוהה, לא סלנג מוגזם.
* בלי מקפים ארוכים (—). בלי אימוג'ים בתוך הטקסט.
* משפטים קצרים. מדריך קורא את זה בטלפון תוך כדי הליכה.
* בלי הבטחות שיווקיות ("משחק מדהים שכולם יאהבו").
* אין להמציא מקורות יהודיים, ציטוטים או ייחוסים לחז"ל. אם אין ודאות - לא כותבים.

## 7. גיוון - מה נחשב batch טוב

* לא כל המשחקים באותה אנרגיה ובאותו מבנה קבוצות.
* לפחות שליש מכל batch צריך להיות `shabbat: true` (אלא אם ה-batch מוגדר אחרת).
* לפחות 3 משפחות משחקים שונות בכל 10 משחקים.
* משחקים שדורשים שקט וריכוז חשובים בדיוק כמו משחקי ריצה - הם אלה שמאפשרים לעבור למסר.

## 8. פורמט הפלט

קובץ JSON יחיד, UTF-8, מערך של אובייקטים:

```json
[ { ...משחק... }, { ...משחק... } ]
```

בלי הערות, בלי טקסט מסביב, בלי BOM. אין להוסיף שדות שלא מופיעים ב-schema.
